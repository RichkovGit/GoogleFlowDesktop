# Видеокарта и монтаж

Flow Studio использует WPF / Direct3D и не встраивает Chromium, Electron или WebView. Windows определяет адаптер интерфейса. Предпочтение высокопроизводительной GPU записывается только для текущего EXE в `HKCU\Software\Microsoft\DirectX\UserGpuPreferences`, сохраняя остальные параметры приложения. Администратор не нужен; после изменения нужен перезапуск.

Генерация Flow выполняется в облаке Google. Локальная GPU ускоряет видеокодирование, а CPU обслуживает сеть, файлы, звук и общие фильтры монтажа. WPF render tier показывает аппаратные возможности, а не имя выбранного Windows адаптера.

## NVIDIA, AMD и Intel

`HardwareService` получает все адаптеры из Windows CIM. Для NVIDIA дополнительная телеметрия берётся из `nvidia-smi.exe` в системном или стандартном каталоге NVIDIA. Путь из текущей папки не исполняется. Для AMD и Intel наличие кодировщика проверяет FFmpeg; CIM сам по себе не доказывает поддержку аппаратного экспорта. Объём памяти из CIM приблизительный, особенно для интегрированной графики.

`MediaExportService.ProbeEncodersAsync()` кодирует настоящий тестовый кадр каждым из доступных путей:

| Выбор | Кодировщик | Условие |
| --- | --- | --- |
| NVIDIA | `h264_nvenc` | Рабочий драйвер NVIDIA и NVENC |
| AMD | `h264_amf` | Рабочий драйвер AMD и AMF |
| Intel | `h264_qsv` | Рабочий драйвер Intel и Quick Sync |
| CPU | `libx264` | Явный выбор CPU и разрешение программного экспорта |

Одного названия кодировщика в списке FFmpeg недостаточно. Результаты проверки кешируются на пять минут. Для Quick Sync явно запрашивается аппаратная реализация `MFX_IMPL_HARDWARE`, а не допускающая программную реализацию `auto_any`. Автовыбор использует первый успешно проверенный аппаратный путь в порядке NVENC, AMF, Quick Sync. Он не переключается на CPU при ошибке. Для выбора другого адаптера используйте явный кодировщик; для NVENC конструктор сервиса также принимает индекс NVIDIA GPU. Выбор драйвером конкретного устройства AMF/QSV зависит от системы.

FFmpeg ищется в `tools/ffmpeg.exe` рядом с приложением, рядом с EXE и `%USERPROFILE%\.local\bin\ffmpeg.exe`. Можно передать полный путь в конструктор. Приложение не скачивает FFmpeg автоматически. На проверенной машине используется `%USERPROFILE%\.local\bin\ffmpeg.exe`.

## Монтаж и автоматическая склейка

`ExportTimelineAsync(clips, outputPath, options, progress, cancellationToken)` принимает клипы в порядке монтажа. Каждый `MediaTimelineClip` содержит локальный путь, начало/конец обрезки в секундах исходника, громкость от 0 до 4 и отключение звука. `MediaTimelineOptions` задаёт разрешение, FPS и кодировщик. `InspectAsync` возвращает длительность и наличие звука, не декодируя весь файл.

Перед склейкой каждый клип приводится к одному разрешению с сохранением пропорций и чёрными полями, одной частоте кадров и стереозвуку 48 кГц. Для клипа без аудио добавляется тишина. Видео кодируется выбранным H.264-кодировщиком; обрезка, масштабирование, нормализация FPS, звук и управление процессом могут использовать CPU. Затем подготовленные клипы объединяются без повторного видеокодирования. Можно соединять исходники разного размера, FPS и звуковой структуры.

Результат — новый MP4. Существующие файлы и исходники не перезаписываются. Промежуточные файлы находятся в отдельной подпапке выбранной папки экспорта; только после успеха готовый файл переносится на конечное имя. При отмене FFmpeg завершается, его потоки закрываются, известные временные файлы удаляются. Очистка допускает короткое ожидание освобождения файлов Windows.

FFmpeg запускается напрямую через `ProcessStartInfo.ArgumentList`, без shell. URL, UNC и сетевые диски отклоняются. Concat использует только локальный файловый протокол и созданные приложением имена. Пользовательский текст не становится синтаксисом FFmpeg.

Для старого быстрого пути сохранены `ProbeAsync()` и `ExportConcatNvencAsync()`: CUDA-декодирование / NVENC и копирование аудио, только одинаковые параметры исходных клипов. Новый монтаж использует универсальный `ExportTimelineAsync`.

## Проверено на этой машине

21 октября 2026 года реальные пробы подтвердили NVIDIA NVENC и Intel Quick Sync. AMD AMF отклонён драйвером: AMD-адаптера на этой машине нет. Утверждать реальный тест на AMD оснований нет; проверены контракт аргументов AMF и корректный отказ при отсутствии драйвера.

Реальный монтаж отдельно выполнен через NVENC и Quick Sync: два исходника разных разрешений и FPS, один со звуком, другой без; обрезка до 1 + 0,75 секунды; итог 320×180, 24 FPS, стерео. Независимое декодирование NVENC-результата показало 42 кадра, длительность контейнера 1,77 секунды с учётом аудиопакетов. Проверены громкость, отключение звука, запрет перезаписи и очистка после отмены. Код проверки находится в `MediaEditingSelfTest.cs`, отдельный повторяемый runner — `research/gpu_verification`.

Технические источники: [FFmpeg — видеокодировщики](https://ffmpeg.org/ffmpeg-codecs.html), [фильтры](https://ffmpeg.org/ffmpeg-filters.html), [concat demuxer](https://ffmpeg.org/ffmpeg-formats.html#concat).

## Сохранение входа

`SecureStorage` хранит данные входа в `%LOCALAPPDATA%\FlowStudio\Secrets` через Windows DPAPI `CurrentUser`. Имена ключей хешируются SHA-256, запись атомарная. Файлы авторизации не переносимы между пользователями Windows. DPAPI не защищает от процессов, которые уже работают от имени текущего пользователя. Для отключения аккаунта используется команда самого приложения.
